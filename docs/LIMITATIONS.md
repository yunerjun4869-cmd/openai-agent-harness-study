# 本地执行与运行边界

本项目提供可运行、可检查的教学机制。使用时请按具体章节理解范围。

| 主题 | 已实现 | 尚未实现或需要应用自己完成 |
|---|---|---|
| 文件工具 | resolve 后检查目录边界，拒绝外链和凭证目录，原子替换 | 对抗性目录竞争、硬链接隔离、操作系统级沙箱 |
| 程序执行 | argv 调用、shell=False、输入关闭、超时、输出截断、POSIX 进程组清理 | 任意程序仍能访问宿主权限范围内的系统；临时输出文件没有磁盘配额；脱离进程组的程序不受原组约束 |
| 预算 | 每个 Agent 有轮数/工具数/字符量/累计 token 上限 | 所有子 Agent 共用的货币预算；精确 tokenizer；本次模型请求开始前无法知道其实际完整用量 |
| 网络 | SDK 请求超时 30 秒、最多 2 次重试 | 每次都自动更换模型或网关；自动重放本地副作用 |
| 上下文 | 保留当前完整工具链，删除较旧完整轮次并标记 | 自动语义摘要、检索回填、OpenAI 原生 compaction 接口 |
| 记忆 | 来源、时间、审阅标记、持久化检索 | 自动认证来源；模型生成的来源说明也需要人工或应用核实 |
| 任务 | SQLite 事务、依赖校验、租约、owner/token 栅栏 | 自动续租、分布式数据库、外部副作用的 exactly-once |
| 调度 | 持久化一次性到期任务与显式 run_due | 完整 cron 表达式、后台服务、自启动守护、跨时区日历规则 |
| 团队 | 有界线程并发、独立历史、不同工作目录 | 自动 Git worktree 创建合并；线程强制终止；任务级 OS 沙箱 |
| MCP | OpenAI 托管的真实 HTTPS 远程 MCP，白名单和逐次审批 | 本地 stdio server；OAuth 授权与 token 刷新流程；生产连接管理 |
| 集成章 | 文件、权限、审计、任务、预算 | 所有机制自动开启的完整产品；其他模块按需组装 |
| 工作流 | 成功步骤结果提交后可续跑，输入/版本/顺序隔离 | 自动校验所有产物仍存在；函数实现变化自动识别；副作用绝不重放 |
| 目标 | 固定检查器、工具证据快照、最大尝试次数 | 对任意自然语言目标自动生成完备证明 |

## 恢复为什么不等于“只执行一次”

如果外部操作成功后，程序在写入 journal 前崩溃，恢复时无法知道那次外部操作是否成功。
因此失败步骤可能再次执行。上传、支付、通知等动作应由业务端提供幂等键或去重记录。
任务租约和工作流租约保护的是状态提交；它们不能撤销旧执行者已经产生的外部影响。

## 离线验证和联网验证分别证明什么

离线示例与测试证明协议处理和本地机制在这些案例下工作正常。
HTTP MockTransport 证明安装的 SDK 能序列化请求并解析模拟的服务响应。
它们都不能证明账户已获得某个模型的权限，也不能证明远程 MCP 服务可达或真实模型效果。
请配置自己的 API Key 后，从 s01 的小任务开始验证；远程 MCP 另需自己的服务配置。

## 不隐式改变机器环境

启动器不会安装系统 Python、请求管理员权限或修改系统依赖。
依赖安装放在明确的项目虚拟环境步骤中；API Key 只从环境或项目 .env 读取。
默认工作区与演示临时目录让学习产物易于检查，示例不会自动提交 Git 或发布外部内容。
